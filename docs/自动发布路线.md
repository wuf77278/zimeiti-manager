# 自动发布路线

自媒体管家的自动发布分成两条互补路线：真实上传优先走 `social-auto-upload`，账号后台自动化优先走桌面版独立浏览器窗口和本地扩展桥。

## 路线 1：social-auto-upload

用途：执行真实视频上传。

默认优先平台：

- 抖音
- 小红书

实验平台：

- 视频号：设置 `SOCIAL_AUTO_UPLOAD_ENABLE_TENCENT=true` 后使用上游 `sau tencent`。系统会探测本机 CLI 是否真的支持 `tencent`；实验上传默认保存草稿，未开启时仍回退为人工接管。

实现位置：

- `backend/app/ops/social_auto_upload.py`
- `backend/app/ops/service.py` 的 `social_auto_upload` 发布模式

启用条件：

```bash
export OPS_ENABLED=true
export OPS_ADMIN_TOKEN="replace-with-local-token"
export VITE_ENABLE_OPS=true
export PUBLISHER_EXECUTION_ENABLED=true
export PUBLISHER_RUN_MODE=social_auto_upload
export SOCIAL_AUTO_UPLOAD_ENABLED=true
export SOCIAL_AUTO_UPLOAD_REPO_PATH="/Users/Apple_501/Desktop/自媒体管家/integrations/social-auto-upload"
export SOCIAL_AUTO_UPLOAD_CLI="/Users/Apple_501/Desktop/自媒体管家/integrations/social-auto-upload/.venv/bin/sau"
```

账号登录约定：

```bash
cd "/Users/Apple_501/Desktop/自媒体管家/integrations/social-auto-upload"
.venv/bin/sau douyin login --account <账号名> --headed
.venv/bin/sau xiaohongshu login --account <账号名> --headed
.venv/bin/sau tencent login --account <账号名> --headed
```

运营台账号的 `sauAccountName` 优先作为 `<账号名>`；没有填写时使用账号 `handle`，并自动清理成安全字符串。

## 路线 2：桌面扩展桥

用途：打开每个账号自己的后台窗口，保持登录态隔离，并为后续填标题、正文、上传视频、停在确认发布前提供桥接能力。

当前覆盖平台：

- 抖音创作者中心
- 小红书创作服务平台
- 视频号助手

实现位置：

- `frontend/electron/main.cjs`
- `frontend/electron/account-preload.cjs`
- `frontend/electron/extensions/zimeiti-bridge/`

隔离方式：

- 每个账号一个 Electron 持久化分区：`persist:zimeiti-account-<accountId>`
- 每个账号可配置独立代理
- 不读取用户原生 Chrome profile
- 不把平台密码或 Cookie 写入运营台数据库

当前状态：

- 已加载本地 MV3 扩展
- 已支持平台识别、心跳上报、命令接收
- 尚未实现平台表单自动填写和最终点击发布

## 推荐执行策略

1. 抖音/小红书真实视频发布：优先使用 `social_auto_upload`。
2. 视频号：默认优先使用桌面扩展桥的 `upload_prepare` 或 `browser_prepare`，人工确认发布；需要试用上游自动上传时再开启 `SOCIAL_AUTO_UPLOAD_ENABLE_TENCENT=true`。
3. 所有平台最终提交动作都需要明确运行模式和人工审核流程；默认 `dry_run` 不触达真实平台。

## 安全边界

- 不做平台绕过登录。
- 不保存平台密码。
- 不读取私信正文或联系人。
- 不做刷量、自动评论、批量私信。
- `PUBLISHER_EXECUTION_ENABLED=false` 时，即使误设发布模式，也会回退到 `dry_run`。
